## 2. 为什么瞬时 min 跨 run 不可比（任务②）

1. **极值统计量重尾**: min 是 4 流最慢者的瞬时速率，分布重尾（24h run p50=12 / p95=27.6 / max=1196）。单点 CV=1.83：任何"瞬时 min 阈值"或"跨 run 单点比较"（如 A/B 快筛里 min 3.9 vs 12.4 这类读数）都被毛刺主导——无饿死 run 里 min<1 Mbps 的采样占 27/2815≈1%，且含真 0。
2. **系统性时间漂移**: min 窗均值随 run 进程上行 3–3.6x（首 30min 处于 TCP 爬坡/netem 队列建立期，基线系统性偏低）。首末窗 dpct 主要测这个漂移的相位，+14%~+91% 的摆幅使 30% 阈值在噪声带内形同虚设——这批数据恰好全为正所以没炸，换一个起始相位即可能输出 -40% 假 FAIL。
3. **跨 run 差异 < run 内摆幅**: 24h 与 FAILED-4h 的窗均值摆幅区间 [9.9,35.8] 与 [11.0,32.5] 几乎完全重叠。两个 run 的首末窗 dpct（+79.6% vs +39.5%）差异 2 倍，纯粹来自相位，不携带系统状态信息。
4. **"FAILED-4h" 并非饿死样本**: 其 min_mbps 低值段最长仅 4 个连续采样（~2min @0.13Mbps，第 178–195min 之间零散），无持续钉死段；现行判定十项重放 min 腿亦 OK。其 FAILED 标签来源无法从现有产物追溯（regression.md 空）。**现有历史数据中不存在确诊饿死样本**——这决定新指标的饿死腿只能用注入法验证（§4.2）。
5. **仪表链可靠性（本分析发现的硬缺陷，三处）**:
   - `samples.jsonl` **100% 行非法 JSON**：采集时字段名/值错位（`"tcp_estab":inuse,"tcp_inuse":orphan`，裸词标签当值），四个 run 全部 282/48/1/2 行无一可解析。Wave-1 支线若以此文件为数据源将全部踩坑。
   - `streams/stream-*.jsonl` 恒零（24h run 397 行全为 0）：**per-stream 速率数据不存在**。任何依赖"最慢流单独速率"的指标（含流速率滚动窗 p10）在此数据上不可实现。
   - `timeseries.csv` 第 8–12 列标签错位（`inuse,<estab值>,orphan,<inuse值>,0` 顶替 `tcp_estab..conntrack_used`），soak_analyze.sh 按 `a[10]` 读 orphan 时读到字符串 "orphan"（awk 算术=0，**orphan 泄漏检测恒 0 永不报警**），`a[12..15]`/`a[19]` 串列导致 psi/load/mem 判定各自读到相邻列。**现行 regression 十项中只有 total/min/p50/active 四项读数可信。**

## 3. 替代指标规格（任务③）

核心思想: 饿死的签名是"**最慢流塌陷而其余流健康**"（min 崩 + p50 正常），且**持续**（真实钉死以分钟–小时计，孤点毛刺以采样计）。单看 min 绝对值无法区分"整体拥塞"与"单流饿死"，必须联合 p50；单看瞬时无法区分毛刺与钉死，必须加持续性。

```
输入:   timeseries.csv；有效采样 = active_streams > 0
flag(t) = (min_mbps < FLOOR) AND (p50_mbps > HEALTHY)
        FLOOR=1.0 Mbps, HEALTHY=5.0 Mbps

S 快腿: 连续 ≥6 个有效采样 flag=1（≈3min）              → FAIL（急性钉死）
W 慢腿: 任一 118 采样（≈60min）滚动窗内 Σflag ≥ 15（窗占比≥12.7%）→ FAIL（慢性/间歇饿死）
判饿死 = S ∨ W；否则 PASS
```

参数依据（全部来自 24h run 实测）:
- FLOOR=1.0: 低于钉死地板（DRS 亚稳态输家 ~0.32 Mbps），高于无饿死 run 的毛刺带（p1=0.4 的孤立点会被持续性条件过滤）；对正常流速率（p50=12）有 12x margin。
- HEALTHY=5.0: 无饿死 run 的 min 窗均值下界 9.9，其余流健康时 p50 常态 >5；区分"单流塌"与"整体拥塞"（整体拥塞时 p50 同崩，flag=0，不误报）。
- streak 6 采样 / 窗占比 12.7%: 对 24h run 实测最大值（S=2、W=4）留 3x / 3.75x margin。
- W 腿窗口占 run 中段任意位置，修复现行"只看首末 30min、中段饿死不可见"的盲区。

## 5. 局限

- 历史数据无确诊饿死样本，饿死腿验证依赖注入形态（0.3 Mbps 恒定钉死）真实性；若真实饿死伴随 p50 同步下降（整体拥塞型），按设计 flag=0 不报——那是另一类问题（容量不足），不该由饿死指标承担。
- 阈值由单一 24h run 校准；换 netem 条件（loss/RTT）或流数后 FLOOR/HEALTHY 需重校。
- 采样间隔 ~31s 假设固定；间隔漂移会使 streak 的物理时长漂移。
- p50 列本身来自同一份有错位争议的 CSV（但第 3/4/5 列数值验证可解析、量纲合理）。
